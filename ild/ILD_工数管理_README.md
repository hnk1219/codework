# ILD_工数管理.xlsx 作成目的と経緯

このファイルは、別PC(会社PC)の Claude が、`ILD_工数管理.xlsx` の目的・構造・作成経緯・編集時の注意点を理解できるように書いた引き継ぎメモ。
Excelの中身は `ild/ILD_工数管理.xlsx`。この文章だけ読めば、仕様と過去の判断理由が分かるようにしてある。

## 1. 作成目的

- 3Dモデリング(キャラクターモデル)の制作で、複数の作業者が複数のアセットを担当している。
- クライアントの確認待ち(提出後の返答待ち)の間は、手戻りにならないよう別のアセットを進める運用をしている。
- そのため、次をひと目で把握したい。
  - どのアセットに何人日かけたか(使用工数)
  - あと何人日かけられるか(残工数)
  - 作業者ごとの状況(今何をしていて、何を抱えていて、手が空いているか)
  - 工程の流れ(ガント)
- 入力の手間を最小にすること。運用の手間が増えて本末転倒にならないことが最重要の要件。

## 2. 入力の考え方(最終仕様)

入力するのは次の3種類だけ。

1. アセット名(新しいアセットが発生したとき、空き枠に1回入力)
2. 工数(予算の人日。使うフェーズ分だけ)
3. 開始日と中断日(回ごと。最大12回)

そのほかは自動計算。

- 使用工数 = 各回の「開始日〜中断日」の平日の日数の合計(土日と祝日シートの日付は除く)。中断日が空の回は今日までを数える。
- つまり、日々の作業ログは付けない。「開始」と「中断」の日付だけで使用工数を推定する。
- 中断日は、提出日とは限らない。作業者が手を止めた日(作業の中断日)を入れる。提出日で工数を数えると実作業とずれるため、開始・中断で管理することにした。
- 再作業(手戻り)で作業を再開したら、次の回の「開始」に日付を入れる。
- 回は1フェーズにつき12回目まで入力できる。
- 新しいアセットの追加・担当変更の手順は4.1を参照。

## 3. ブック構成

シート順は変わることがある(ユーザーが並べ替える)。名前で扱うこと。

| シート | 役割 |
|---|---|
| 工数管理 | 入力と集計の本体 |
| 実作業Gantt | 工数管理の日付から自動で作る横スクロールの工程表。入力は不要(以前の名前は Gantt) |
| 祝日 | 使用工数の日数から除く日付の一覧(2026〜2027年の祝日、年末年始12/29〜1/4)と、作業者の空き日数を出す集計用カレンダー |

ブック内の説明シート(info)は廃止した。運用手順は、このREADMEの4.1(アセットの追加・担当変更)、2(入力)、4.4(状況)、4.7(日付の色)にまとめてある。

## 4. 工数管理シートの構造

### 4.1 全体レイアウト

- 作業者ごとのセクション(見出し行)に分かれている。作業者は3人想定(CH01, CH02, CH03)。最後に「未割当」セクション。
- 各セクションの見出し行のすぐ下に、アセットの枠(4行1組)が並ぶ。
- 見出し行のA列に作業者名を直接入力する。担当は、アセットがどのセクションにいるかで決まる。
- 各セクションの先頭には空き枠が1つある。新しいアセットは、その枠の一番上の行(total行)のA列にアセット名を入れる。
- 空き枠を使い切ったら、一番上の枠(4行)をコピーして、見出しのすぐ下の行に「コピーしたセルの挿入」をし、新しい枠のアセット名・工数・FIX・日付を消す。新しいアセットが上に並ぶ。
- 担当を変えるときは、4行の枠ごと別セクションへ切り取り、「切り取ったセルの挿入」で移す。

### 4.2 アセットの枠(4行)

上から次の順。

1. total行: アセット名(A列に手入力)。工数・使用・残・消化率の合計(薄い青の塗り、太字)
2. low
3. high
4. fac

フェーズの順序は low → high → fac(ユーザー指定)。

### 4.3 列

見出し(1行目)は、ユーザーが英語表記に変更した。

| 列 | 見出し | 内容 |
|---|---|---|
| A | assetID | アセット名。total行のみ手入力、ほかの3行は自動(totalの値) |
| B | task | total / low / high / fac のラベル(数式) |
| C | assign | 非表示。以前は担当を表示していたが不要になり、中身は空 |
| D | 工数 | 予算の人日(low/high/facは手入力、totalは自動合計) |
| E | 使用 | 使用工数(自動) |
| F | 残 | 工数 − 使用(自動) |
| G | 消化率 | 使用 ÷ 工数。total行と作業者の見出し行は平均値(下記) |
| H | status | 状況(自動) |
| I | day | 中断状態の経過日数(フェーズ行)。作業者の見出し行では作業者の空き日数 |
| J | FIX | フェーズ完了のとき ○ を入れる(プルダウン) |
| K〜AH | 1〜12 | 回ごとの「開始」「中断」の日付(2列で1組、12組) |

### 4.4 状況(status)の判定

フェーズ行ごとに自動判定。

- FIX欄が入力済み: FIX
- 開始も中断も空: 未着手(工数が入っている場合)
- 開始の数 > 中断の数(最後の回が作業中): 作業中(再作業の回も含めて「作業中」)
- それ以外: 中断(提出後の返答待ちなど)
- 工数が空のフェーズ行は状況も空(その行は薄い灰色で表示される。工数をまだ入れていない行の目印)

状況の種類は、未着手 / 作業中 / 中断 / FIX の4つ。

用語の変更履歴: 「確認待ち」→「中断」、「手戻り中」→「再対応」→(会社PC側で)「作業中」に統合、「手が空く(中断のみ)」→「作業待ち」、「工数超過・要相談」→「工数超過」。

### 4.5 消化率の計算ルール

- フェーズ行: 使用 ÷ 工数。
- total行: 状況が「未着手」「作業中」でないフェーズの消化率の平均(単純平均)。
- 作業者の見出し行: 状況が「FIX」のフェーズだけの消化率の平均。

### 4.6 作業者の見出し行の集計

- B: 作業中の件数。C(assign列)は非表示で不使用
- D: 担当の全フェーズの工数の合計(FIX含む)
- E: 担当の全フェーズの使用の合計(FIX含む)
- F: FIX以外のフェーズの残の合計
- G: FIX フェーズの消化率の平均
- H: 状況(作業中 / 作業待ち / 着手待ち / 空き / 工数超過)。作業中のフェーズがあり、その残の合計が0以下なら「工数超過」。作業中がなく中断があれば「作業待ち」、未着手だけなら「着手待ち」、何もなければ「空き」
- I(day): その作業者が何の作業もしていない平日の日数(最初の作業日〜最後の作業日の間で、どのアセットも作業していない日。祝日除く)

### 4.7 日付の矛盾の色表示(開始〜中断の日付セル)

- 赤: 中断が開始より前 / 開始か中断が抜けている(後の回が入力済み) / 前の回の中断より前に次の開始がある
- オレンジ: 同じ作業者の別の枠と期間が重なっている(境界の日が同じだけの場合や、同じ日だけの作業は対象外)
- 開始と中断が同じ日は正常(1日だけの作業がある)。色は付けない。

## 5. 実作業Gantt シート

- 工数管理の開始・中断の日付から自動生成。横スクロール前提(左の作業者・アセット・フェーズ・状況の列は固定)。
- 日付の列は平日のみを左詰めで並べる(土日祝の列は削除)。B1の日付で表示開始日を指定。2026/6/1から240平日分。
- 作業者ごとに濃い紺色の帯の見出し行が入り、その下に担当のアセットが並ぶ。作業者ごとの背景色分けは不要(外した)。
- 青=開始〜中断の期間、緑=作業中(中断が空の回、今日まで)、薄い黄=その作業者が何の作業もしていない期間(作業待ち。日付の入力がない平日のうち、今日まで。今日より先は付けない。見出しの帯には付けず、アセットの行だけ)、薄い橙=今日。
- 日付が入っているフェーズ行だけが並ぶ(最大120行)。
- 並べる順の制御には、工数管理の非表示列(BP列)と、Gantt の非表示列・非表示行(126〜128行の作業待ち判定)を使っている。

## 6. 祝日シート

- A列=日付、B列=名称。使用工数の NETWORKDAYS が、祝日!$A$2:$A$200 を除外日として参照する。
- 会社の休業日なども、この列に追加できる。
- H〜L列は、作業者の空き日数を出す集計用カレンダー(2026/6/1から300日分)。先頭の日付は変更可。

## 7. 内部構造(編集する人向け)

工数管理シートには非表示の補助列がある。消さないこと。

| 列 | 内容 |
|---|---|
| AI1 | =TODAY() を1セルに集約(各行に TODAY() を置くと重くなるため) |
| AJ | セクション見出し行の目印。見出し行は作業者名(未割当は "-")。フェーズ行はこの列を上へたどって担当を決める(LOOKUP) |
| AK〜AO | 見出し行集計用: 担当名、状況、工数、使用、残(フェーズ行のみに数式) |
| AQ〜BN | 日付の重なり判定用。回ごとに COUNTIFS で同じ作業者の他の枠との重なりを数える |
| BO | フェーズ行の消化率(見出し行の平均計算用) |
| BP | Gantt に並べる行の順序用(日付があるフェーズ行と見出し行の行番号) |

設計上の判断:

- 見出し行の集計は、必ず非表示の補助列(AK〜AO、BO)だけを参照する。見出し行自身のセルを含む範囲を参照すると循環参照になる(過去に発生して修正した)。
- フェーズ行の数式は、行相対の参照で書いてある。枠をコピーして挿入しても、そのまま動く。

## 8. 作成経緯(時系列)

1. 相談の開始
   - 目的は、複数アセット・複数人の工数を、パッと見で把握すること。
   - 最初は、Excelで「アセットID・フェーズ・作業者・工数・消費工数・作業開始日・作業中断日」の表を提案した。
2. 最初のExcel版
   - アセット管理、作業ログ(1日1行追加)、提出履歴、作業者別、アセット別、マスタの複数シート構成を作った。
   - 実際に使ってみると、手動入力の項目が多く、運用の時間がかかって本末転倒になった。新しいアセットを手動で登録する手間も負担だった。
3. 簡素化の方針転換
   - 「提出日時と工数を入力したら、使用工数と残りが分かる」ことだけに絞った。
   - 日々の作業ログ、繰越、マスタなどを削除。
   - 1アセット=4行の枠(fac/high/low+合計)にし、空き枠にアセット名を入れるだけで追加できる形にした。
   - 日付の入力は、提出日ではなく作業者が付ける開始・中断の日付にした。回数は12回まで。
4. 構造の整理
   - 作業者ごとのセクションに分け、作業者別シートは廃止して、各セクションの見出し行に集計を統合した。
   - 担当はセクションで決まる形にして、assign列は不要になり、非表示にした。
   - 空き枠は各セクション1つにした。
   - 合計行を total に改名し、一番上に移して色を付けた。フェーズの順は low → high → fac に変更した。
5. 精度の改善
   - 祝日シートを作り、使用工数から祝日と年末年始を除くようにした。
   - 日付の矛盾(開始と中断の逆転、抜け、重なり)を色で表示するようにした。
   - 消化率の平均のルールを、total行と見出し行で別々に決めた(4.5参照)。
   - 作業者の空き日数(作業待ち)を、見出し行の day に出すようにした。
6. ガントチャートシートの追加と調整
   - 開始・中断の日付から自動でガントチャートを作った。
   - 土日祝の列を省き、作業者の区切りを帯で表示。作業者が何の作業もしていない期間を薄い黄色にした。
7. 状況の整理(会社PC側での更新)
   - 2026-10-07 21:39 に、状況の「再対応」を「作業中」に統合した(再作業の回も作業中として扱う)。
   - Gantt シートの名前を「実作業Gantt」に変更。ファイル名を `ILD_工数管理.xlsx` に変更し、`ild/` フォルダへ移動した。
8. 不具合の修正
   - 循環参照: 見出し行の集計が自分自身を含む範囲を参照していた。補助列に分けて解消した。
   - 日付入力が重い: 条件付き書式の重なり判定がシート全体を毎回計算していた。補助列と COUNTIFS に分け、TODAY() も1セルに集約した。

## 9. 編集するときの注意(Excelファイルを加工する場合)

- Excelで保存されたファイルを openpyxl で読み書きすると、次が失われることがある。
  - プルダウン(入力規則)のうち、他シートを参照するもの。Excelが拡張形式で保存するため、openpyxlが読めない。保存のたびに付け直すこと(FIX欄のプルダウンは固定文字列「○」の一覧)。
  - 他シートを参照する条件付き書式。同じく拡張形式になる。条件付き書式は、そのシート内のセルだけを参照して作ること(過去に、他シート参照の判定をシート内の非表示行に移して対処した)。
- エラーチェックの緑の三角は、sheet XML の `ignoredErrors` を追記して抑制している(保存し直すと消えるので、必要なら付け直す)。
- 条件付き書式を openpyxl で一部だけ削除するときは、`ws.conditional_formatting._cf_rules[cf]` のリストを in-place で更新する。`cf.rules = ...` と代入しても保存に反映されない。
- ユーザーはExcelで直接編集・保存している。編集前に必ず最新のファイルを読み込み、ユーザーの変更を上書きしないこと。ファイルがExcelで開かれていると書き込めない(ロックされる)ので、閉じてもらう。
- 列を削除・挿入すると、数式の列記号がずれる。Excel上で行う分には自動で追従するが、スクリプトで編集する場合は列の位置を確認すること。
- 数式を変更したら、Excelでの再計算結果を確認してもらう。LibreOffice等の環境がないと、こちらでは計算結果を検証できなかった。

## 10. 運用上のルール(ユーザーの方針)

- 回答は日本語で簡潔に。絵文字は使わない。
- 指示のないことはやらない。1つの修正のついでに、無関係な要素の見た目を変えない。
- 作業の開始時は git pull をする(自宅PCと会社PCで同じリポジトリを使っているため)。
- 業務のデータが入っているため、push する前に確認する(今回は「工数管理.xlsxは push してよい」と許可済み)。
